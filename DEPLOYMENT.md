# Neon + Render + Vercel deployment

This repository is split into a Django API (`backend/`) and a Vite/React site (`frontend/`). Deploy the database first, then the API, then the site.

## 0. Before deployment

1. Push this project to a GitHub repository. Keep `.env`, `.env.local`, and Neon credential files out of Git. The repository now ignores these files; check `git status` before pushing.
2. Rotate the Neon database password/credential before deploying. A real connection string had been placed in `backend/.env.example`; that file is now redacted, but the previous value may still exist in Git history or a remote repository. In Neon, reset the role password (or create a new restricted role), then use the new connection string. Do not paste credentials into code or commit them.
3. In Neon, open the project and copy the connection string for the database and role you will use. Prefer the pooled connection string for the web application; retain the `sslmode=require` option. You will paste it into Render as `DATABASE_URL`.

## 1. Deploy the API to Render

1. In Render, choose **New + → Blueprint** and connect the GitHub repository. Select the project branch. Render reads the root `render.yaml` and creates the `mahir-showroom-api` web service.
2. The blueprint sets the service root to `backend`, installs `backend/requirements.txt`, collects static files, starts Gunicorn, and checks `/api/health/`.
3. Open the new service's **Environment** page and set:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | The rotated Neon connection string (keep it secret) |
   | `ALLOWED_HOSTS` | The Render API host only, without `https://`, e.g. `mahir-showroom-api.onrender.com` |
   | `CORS_ALLOWED_ORIGINS` | The Vercel site origin, e.g. `https://mahir-showroom.vercel.app` (no path, comma-separated if using more than one origin) |

   `SECRET_KEY` is generated by the blueprint. Keep `DEBUG=False` and `DJANGO_SETTINGS_MODULE=config.settings.production` as configured. `ALLOWED_HOSTS` is the backend's host; `CORS_ALLOWED_ORIGINS` is the browser frontend's full origin.
4. Save the environment variables and deploy/redeploy. Wait for Render's health check to pass. Open `https://<your-api-host>/api/health/`; it should return `{"status":"ok"}`.
5. The Render start command runs `python manage.py migrate --noinput` before Gunicorn starts. Confirm the deploy logs show migrations completed. If the service was created before this start command was configured, open the Render service's **Shell** and run `python manage.py migrate` against its configured `DATABASE_URL`; this creates any missing Django and SimpleJWT blacklist tables while preserving existing data. Then run `python manage.py createsuperuser` only if the database does not already have an admin.
6. Open `https://<your-api-host>/admin/` and sign in. Add the showroom records, categories, and products; then add showroom users from the app as described in the main README.

If the API fails to start, check Render **Logs** and confirm `DATABASE_URL`, `ALLOWED_HOSTS`, and `SECRET_KEY` are set. The API URL used below is the HTTPS service URL without a trailing slash, followed by `/api`.

If login logs report `relation "token_blacklist_outstandingtoken" does not exist`, the SimpleJWT blacklist migration has not reached the connected database. Run `python manage.py migrate` once in the Render service Shell, then retry login. In the deploy logs, confirm `token_blacklist` migrations are marked `OK` before testing authentication.

## 2. Deploy the frontend to Vercel

1. In Vercel, choose **Add New → Project**, import the same GitHub repository, and select the branch.
2. Set **Root Directory** to `frontend` (enable the option to include files outside that directory only if Vercel asks; this app does not need them).
3. Use the Vite defaults or set **Framework Preset** to **Vite**, **Build Command** to `npm run build`, and **Output Directory** to `dist`. `frontend/vercel.json` provides the SPA rewrite so direct visits/reloads on React routes serve `index.html`.
4. Add this project environment variable for **Production** (and Preview too if you want preview builds to use the same API):

   | Variable | Value |
   |---|---|
   | `VITE_API_URL` | `https://<your-api-host>/api` |

   This value is public and becomes part of the browser bundle; never put the database URL or Django secret in a `VITE_*` variable.
5. Deploy. If you add or change an environment variable later, trigger a new deployment because Vite embeds it at build time.
6. Copy the final Vercel **Production Domain** (origin only, e.g. `https://mahir-showroom.vercel.app`) into Render's `CORS_ALLOWED_ORIGINS`, save, and redeploy the API. If you use a custom domain, add that origin too. CORS origins must match the browser URL exactly, including `https://`, and must not have a trailing slash or path.

## 3. Verify the full deployment

1. Open the Vercel URL and sign in with the admin/showroom user created above.
2. In browser developer tools → **Network**, confirm API requests go to `https://<your-api-host>/api/...` and succeed. A browser CORS error usually means the Vercel origin in Render is missing or misspelled.
3. Reload a nested page directly; it should still load (Vercel SPA rewrite).
4. Create a small test record and confirm it appears after refreshing. Use the admin/API and Neon console to confirm data is in the intended database.

## Local environment files

- Backend: copy `backend/.env.example` to `backend/.env`; set `DATABASE_URL`, `SECRET_KEY`, and local values there.
- Frontend: copy `frontend/.env.example` to `frontend/.env`; use `VITE_API_URL=http://localhost:8000/api`.
- Do not commit either `.env` file. Render and Vercel production values belong in their respective dashboard environment settings.
